# 구현 트릭

기능별 목적, 방법(트릭), 다른 기능과의 관계. 끝에 관계 요약표.

## 공통 원칙

- **전환은 시스템 단축키로만**: 입력 소스를 직접 고르지 않고 `이전 입력 소스 선택` 단축키(F-키)를 눌러 전환. 한글 조합이 끊기지 않고 입력기 상태가 꼬이지 않음
  - 예외: 영어처럼 특수문자 입력, 메뉴의 한국어/영어 선택
- **접근성 권한**: 전환은 이벤트 탭으로 하므로 필수. 권한이 없으면 활성화를 끄고(매핑·단축키 원복) gksdud 탭 외 설정을 비활성화. 다시 허용해도 활성화는 직접 켬
- **자기 이벤트 표시**: 합성한 키 이벤트의 `eventSourceUserData`에 실행마다 바뀌는 난수를 넣어, 이벤트 탭이 자기 이벤트를 다시 처리하지 않음
- **입력 내용 비저장**: 합성하는 키는 F-키뿐. 일반 입력은 Option 특수문자 처리 중에만 잠깐 큐에 담음
- **지연 작업은 세대 번호로 무효화**: 타이머 작업은 만들 때의 세대 번호를 기억하고, 그 사이 새 전환이 시작됐으면 실행하지 않음
- **입력 포커스 유지**: 입력 중 오류는 모달 대신 해당 체크박스 툴팁이나 상태 문구로 표시

## 한영 키 매핑

- **목적**: Karabiner 없이 원하는 키를 한영 키로 사용, Caps Lock 전환 딜레이 제거
- **방법**
  - 키보드마다 HID `UserKeyMapping`으로 선택한 키(우측 ⌘·⌥·⌃, Caps Lock)를 대상 F-키(F13~F20, 기본 F19)로 변경
  - `com.apple.symbolichotkeys` 60번(이전 입력 소스 선택)을 그 F-키로 설정하고 `activateSettings -u -virtualSession`으로 즉시 반영. `-virtualSession`이 없으면 마우스 가속 같은 물리 장치 설정까지 다시 적용됨
  - 쓰기 전에 되돌릴 정보(원래 매핑, 쓰려는 대상)를 먼저 저장하고, 쓴 뒤 다시 읽어 확인. 해제·종료 시 우리가 쓴 매핑만 원래대로 복원
  - 1초마다 매핑을 확인해 재연결, Karabiner 가상 키보드 재생성, 잠자기 복귀 후 다시 적용
  - 화면이 잠겼거나 다른 사용자 세션이 앞에 있으면 매핑을 원래대로 돌리고, 돌아오면 다시 적용. 잠금화면에서는 이벤트 탭이 키 누름을 받지 못해 Caps Lock 한영 키로 대문자를 끌 수 없음. 잠금 여부는 보안 입력이 아니라 `CGSessionCopyCurrentDictionary`로 확인하고, 잠금 알림으로 바로 반영
  - 재부팅하면 HID 매핑이 사라지고 레지스트리 ID가 다른 장치에 재사용되므로, `kern.bootsessionuuid`가 바뀌면 기록 삭제
  - 레지스트리 ID는 연결마다 바뀌므로 키보드별 설정은 Vendor/Product/시리얼 등의 해시로 저장
  - 기본 입력기 메뉴바 아이콘은 `com.apple.TextInputMenu`의 `visible`을 끄고 `TextInputMenuAgent`를 재시작해 숨김. 메뉴바에 표시가 꺼져 있거나 'Mac 입력기 아이콘 대체'를 끄면 숨기지 않음
- **관계**
  - 대상 F-키를 다른 시스템 단축키나 다른 매핑이 쓰고 있으면 적용하지 않음
  - Caps Lock을 한영 키로 쓰면 macOS에는 F-키로만 전달되어 Caps Lock 기능이 사라짐. 대문자는 길게 누르기로

## 누를 때 전환

- **목적**: macOS 단축키는 키를 뗄 때 전환되어, 빠르게 입력하면 한 글자가 이전 입력 소스로 들어감
- **방법**
  - 세션 이벤트 탭에서 F-키 누름을 막고, 같은 F-키의 누름·뗌 쌍을 곧바로 HID 단계(`.cghidEventTap`)에 보냄. 시스템 단축키 처리 전에 들어가 즉시 전환
  - 수정키는 지우되 F-키 식별 플래그(SecondaryFn)는 유지해야 단축키와 일치
  - 반복 입력과 실제 키 뗌은 막아 한 번만 전환
- **관계**: 권한이 없으면 활성화가 꺼짐

## Space 조합 한영 키

- **목적**: ⌃·⌘·⌥ + Space를 한영 키로 사용. HID 매핑으로는 조합을 바꿀 수 없음
- **방법**
  - 이벤트 탭에서 Space + 정확히 한 수정키를 잡아 Space를 막고, F-키 누름·뗌 쌍을 새로 만들어 보냄
  - 같은 Space의 반복과 뗌도 막음(수정키를 먼저 떼도)
  - HID에 쓰지 않으므로 모든 키보드에 적용
- **관계**
  - 키보드별 설정에는 없음
  - 고른 조합의 원래 기능(예: ⌘ + Space Spotlight)은 가려짐. 고르지 않은 조합은 그대로
  - Option 특수문자 처리보다 먼저 확인해서 ⌥ + Space가 특수문자 쪽으로 가지 않음

## 길게 눌러 대소문자 전환

- **목적**: 한영 키를 0.5초 누르면 영어로 전환하고 Caps Lock 토글. 누르는 즉시 전환하므로 딜레이 없음
- **방법**
  - 누르는 순간 전환하고 0.5초 타이머 시작
  - 0.5초가 지나면 영어인지 확인하고 `IOHIDSetModifierLockState`로 Caps Lock 잠금을 직접 설정. Caps Lock 키 이벤트를 합성해도 잠금은 바뀌지 않음. 설정 직후 읽은 값은 늦게 바뀌기도 해서 다시 읽어 확인하지 않음
  - 한글이었으면 F-키로 영어 전환을 요청하고, 입력 소스 변경 알림에서 영어가 확인되면 Caps Lock 설정. 0.5초 안에 확인되지 않으면 취소하고 툴팁에 표시
  - 누른 앱이 바뀌면 취소
- **관계**
  - 영어와 한국어가 최근 두 입력 소스여야 함
  - 대소문자 보존이 켜져 있으면 기억한 영어 대소문자를 기준으로 토글

## 한영 전환 대소문자 보존

- **목적**: 한글 입력기는 한글로 들어갈 때 Caps Lock을 끔. 영어로 돌아오면 원래 대소문자로 복원
- **방법**
  - 영어 대소문자를 실제 Caps Lock과 따로 기억(`EnglishCapsState`)
  - 전환 중의 Caps Lock 변화는 입력기가 끈 것으로 보고 무시. 입력기는 한글로 들어갈 때만 끄므로, 영어 밖에서 영어로 가는 전환 중에 누른 Caps Lock은 기억
  - 입력 소스 알림과 입력기의 Caps Lock 끔은 순서가 일정하지 않아, 전환 후 0, 0.05, 0.15초에 확인하고 다르면 복원
  - 기억은 세션 한정. 활성화할 때 현재 Caps Lock 상태로 시작
- **관계**: 길게 누르기와 따로 켜고 끌 수 있음

## 한글 상태에서도 Caps Lock으로 대소문자 전환

- **목적**: 한글에서 Caps Lock을 눌러 영어로 돌아갈 때의 대소문자를 변경. 한글에서도 Caps Lock 불빛이 영어 대소문자와 일치
- **방법**
  - 한글에서 누른 Caps Lock도 기억한 영어 대소문자로 저장하고, 한글에서도 Caps Lock을 그 값으로 복원. 2벌식은 Caps Lock과 관계없이 한글이 입력되어 2벌식에서만 동작. 다른 자판은 확인하지 않음
  - 한글 입력기가 전환 알림 뒤 0.1초쯤 늦게 Caps Lock을 끄기도 해서, 한글로 전환할 때만 0.3초 확인 추가. 이 0.3초 동안 누른 Caps Lock은 무시됨
- **관계**
  - 대소문자 보존이 켜져 있어야 동작. 대소문자 보존을 끄면 함께 꺼짐
  - Caps Lock을 한영 키로 쓰면(기본값·키보드별 어디든) 사용 불가. 켜진 상태에서 Caps Lock을 한영 키로 고르면 경고 후 끔
  - 꺼지면 한글에서 켜 둔 Caps Lock도 끔

## ESC 누를 시 영소문자로 변경

- **목적**: vim 등에서 한글 상태로 ESC를 누르면 이후 명령이 한글로 입력되는 문제 방지
- **방법**
  - ESC 누름(수정키 조합·반복 제외)에서 한글이면 F-키로 영어 전환 후 Caps Lock 끔, 영어 대문자면(복원 전인 기억한 대문자 포함) Caps Lock만 끔. ESC는 막지 않고 앱에 그대로 전달
  - 입력 소스 확인과 전환은 ESC를 넘긴 뒤 이벤트 탭 밖에서 함
  - 길게 누르기의 전환 경로(영어 확인 후 Caps Lock 설정)를 재사용. ESC는 창을 닫는 경우가 많아 앱이 바뀌어도 취소하지 않음
  - 직전 한영 키 전환이 아직 반영 전이면(0.5초 이내, 입력 소스 그대로) 한글에서는 F-키를 다시 보내지 않고, 영어에서는 한 번 더 보내 영어로 돌아옴. 두 번 전환되면 원래 입력 소스로 돌아가기 때문
  - 다른 입력 소스(일본어 등)는 그대로. F-키는 이전 입력 소스로만 전환하기 때문. 보낸 F-키가 영어가 아닌 다른 입력 소스로 가면 0.5초 뒤 되돌림
- **관계**
  - 영어와 한국어가 최근 두 입력 소스여야 함
  - 길게 누르기 전환이 진행 중이면 새로 전환하지 않고 목표만 소문자로 변경. 이후 앱이 바뀌어도 취소하지 않음
  - 대소문자 보존이 켜져 있으면 기억한 영어 대소문자도 소문자로

## 입력 소스 추가

- **목적**: 한국어·영어 외 입력 소스(중국어·일본어 등)를 함께 사용. 순회는 한영 키로 목록 순서대로, 분리는 전환 키로 입력 소스 하나와 한/영 사이를 전환
- **방법**
  - 전환은 그대로 `이전 입력 소스 선택` 단축키(F-키)로만 함. 필요하면 먼저 목표 입력 소스를 백그라운드에서 선택했다가 되돌려, 시스템의 최근 입력 소스 순서만 바꿈
  - 백그라운드 선택은 입력기(한국어·일본어 등)면 앞 앱에 반영되지 않고, 레이아웃(ABC 등)이면 앞 앱이 바로 반영하면서 조합 중인 글자를 버림. 그래서 입력기에서 레이아웃으로는 단축키만 쓰고, 레이아웃이 다음 목표인 입력기로 들어갈 때 그 레이아웃을 이전 입력 소스로 맞춰 둠
  - 한국어가 현재일 때는 레이아웃을 선택하지 않음. 다른 입력기에서 한국어로 올 때는 그 입력기의 조합이 사라질 수 있고, 앱에 레이아웃이 잠깐 반영될 수 있음
  - 서드파티 입력기가 현재이거나 선택 대상이면 두 선택 사이에 50ms를 둠. 연달아 선택하면 앞의 선택이 빠져 단축키가 예전 입력 소스로 갈 수 있음(WeChat 입력기). 호환성 모드를 켜면 모든 입력 소스에 둠
  - 메뉴바 아이콘은 거쳐 가는 입력 소스를 표시하지 않고 도착한 입력 소스만 표시
  - 재배열을 거치는 전환이 도착하기 전에 친 키는 탭에서 붙잡아 두었다가, 도착 알림 30ms 뒤 순서대로 다시 보냄(최대 128개, 0.5초). 앱이 거쳐 가는 레이아웃을 먼저 반영해 영어로 입력되는 것을 막음
  - 도착 전에 전환 키를 또 누르면 도착할 입력 소스를 기준으로 계산. 단축키만 필요하면 바로 보내고, 재배열이 필요하면 도착 뒤 실행(마지막 목적지만 유지)
  - 입력 소스 목록은 변경 알림을 받을 때만 다시 읽음
  - 최근 입력 소스 순서는 입력 소스 알림과 자체 선택으로 추적. 시작할 때는 `com.apple.HIToolbox`의 `AppleInputSourceHistory`로 채움
  - 0.5초 안에 전환되지 않고 목표가 레이아웃이면 목표를 다시 선택해 앞 앱과 표시를 맞춤
  - 분리 키는 한영 키처럼 HID로 매핑하되 대상 F-키를 따로 씀(F18부터, 한영 키의 F-키와 수정키 없는 시스템 단축키가 쓰는 F-키는 건너뜀). 시스템 단축키 없이 이벤트 탭에서만 처리. Space 조합은 탭에서 처리
  - `CFBundleAllowMixedLocalizations`로 시스템 언어의 입력 소스 이름을 받음. 아이콘은 세 글자까지의 언어 코드, 없으면 순회 순서 번호(10까지, 이후는 빈 칸). 기능이 꺼져 있어도 메뉴바 아이콘은 같은 규칙
- **관계**
  - 끄면 기존과 동일
  - 켜면 길게 누르기·ESC도 최근 입력 소스와 관계없이 영어로 전환
  - 분리 키는 한영 키와 겹칠 수 없음. 한영 키로 고르면 경고 후 분리 키 해제. Caps Lock이면 한글 상태 Caps Lock과 같이 쓸 수 없음
  - Space 조합을 분리 키로 고를 때 같은 조합의 시스템 단축키가 켜져 있으면 경고. 앱 자체 단축키는 확인하지 못함
  - 분리 키의 F-키가 다른 매핑에 쓰이면 분리 키만 적용하지 않음

## Option 특수문자

- **목적**: 한글 상태에서 ⌥ + 문자를 영어처럼 입력(⌥8 → •)하거나, ⌥ + 문자를 일반 문자로 입력
- **방법 (영어처럼 특수문자 입력)**
  - 한글에서 ⌥ + 문자를 막고 영어 입력 소스를 직접 선택. 영어가 확인되면 원래 키 이벤트 복사본을 보내고 0.06초 뒤 한글로 복귀
  - 그 사이 들어온 입력은 큐에 담았다가 한글로 돌아온 뒤 순서대로 다시 보냄(최대 256개). 이어지는 ⌥ 입력은 한 번의 왕복을 같이 사용
  - dead key(예: ⌥E)는 `UCKeyTranslate`로 조합 대기 여부를 미리 확인해, 다음 글자까지 모았다가 한 번에 보냄. 바로 한글로 돌아가면 조합이 사라지기 때문
  - ⌥ + `는 한글 입력기 자체 기호라 그대로 둠
  - 앱 전환, 마우스 클릭, 잠자기면 취소. 한글로 돌아오지 못하면 대기 입력을 버림(영어 상태로 쏟아지지 않게)
- **방법 (Option 문자 입력 차단)**: ⌥ + 글자 이벤트에서 Option 플래그만 제거. 모든 입력 소스에 적용
- **관계**
  - 두 모드 중 하나만 사용 가능
  - 영어처럼 입력은 영어 입력 소스가 있어야 함
  - 처리 중에는 길게 누르기와 대소문자 복원을 멈추고, 끝나면 복원을 다시 예약

## CLI

- **목적**: Hammerspoon, Karabiner 등에서 설정을 바꾸고 입력 소스를 전환
- **방법**
  - 앱 안의 작은 명령(`Contents/Helpers/gksdud`, Foundation만 사용)이 인자를 `CFMessagePort`로 실행 중인 앱에 보내고, 앱이 텍스트와 JSON 결과를 돌려줌. 도움말과 인자 문법 검사는 앱 없이 함(`CLI.swift`를 둘이 공유)
  - 설정은 설정 창의 컨트롤 상태를 바꾸고 그 처리 함수를 불러 같은 검사·경고·적용을 거침. 경고 창은 `runAlert`를 바꿔 `--force`일 때만 '변경'으로 답하고, 오류는 시트 대신 결과로 돌려줌
  - 여러 설정은 적은 순서대로 적용. 컨트롤이 비활성이거나 경고를 거절해 막힌 항목은 나머지 뒤에 다시 시도하고, 끝나면 값을 다시 읽어 뒤의 변경이 되돌린 항목은 실패로 표시
  - 단축키를 적용하며 `Process.waitUntilExit`가 런 루프를 돌리는 동안 온 요청은 '적용 중'으로 거절하고, 명령이 3초까지 다시 요청. 포트는 실행 시 적용을 마친 뒤 염
  - 일시정지는 잠금화면처럼 `away`로 키보드 매핑만 원래대로 돌리고 이벤트 탭을 멈춤. 시스템 단축키와 입력 메뉴는 그대로라 빠름(활성화 끄기는 `activateSettings` 때문에 수백 ms). 저장하지 않음
  - 입력 소스 전환은 입력 소스 추가의 재배열 + F-키 경로(`switchSource`)를 그대로 써서 입력기도 앞 앱에 반영. 입력 소스 추가가 꺼져 있으면 분리 방식처럼 한국어·영어 사이를 이전 입력 소스로 맞춤. 활성화가 꺼져 있으면 단축키가 없어 직접 선택
  - 설치는 `/usr/local/bin/gksdud` 링크. 권한이 없으면 `osascript`의 `with administrator privileges`를 별도 프로세스로 실행(메인 스레드를 막으면 이벤트 탭도 멈춤)
- **관계**
  - 접근성 권한이 없으면 설정 창처럼 대부분 바꿀 수 없음
  - 일시정지 중에는 Space 조합, 길게 누르기, ESC, 특수문자, 대소문자 보존도 멈춤. 활성화를 켜면 풀림

## 메뉴바 아이콘

- **목적**: 기본 입력기 아이콘을 대신해 현재 입력 소스 표시
- **방법**: 입력 소스 변경 알림으로 갱신. 메뉴가 열려 있는 동안은 알림이 늦게 와서 `eventTracking` 모드 타이머로 0.1초마다 갱신

## 서명과 업데이트

- **고정 인증서 서명**: 로컬 인증서로 서명하고 designated requirement를 인증서에 묶어, 업데이트해도 접근성 권한 유지. ad-hoc 서명은 바이너리 해시에 묶여 교체할 때마다 권한을 다시 허용해야 할 수 있음
- **자동 업데이트**
  - GitHub 릴리스 자산의 URL·크기·SHA-256 검사, 링크가 든 압축은 거부
  - 새 앱은 설치된 앱의 인증서 요구사항을 만족해야 함
  - 별도 도우미 프로세스(`--install-update`)가 앱 종료를 기다려 교체하고, 새 앱이 실행 확인 파일을 쓰지 않으면 이전 앱으로 복원

## 테스트 도구

- 아래 `--` 모드는 `TESTS` 플래그로 테스트용 앱에만 컴파일되고 배포 앱에는 없음. `build.sh`가 배포 앱과 함께 테스트용 앱을 만듦
- `--self-test`: 빌드 중 테스트용 앱에서 실행. 가짜 키보드, 가짜 단축키 저장소, 임시 UserDefaults를 써서 실제 HID와 시스템 설정을 건드리지 않음
- `--render-keyboard-ui <폴더>`: 설정 창을 밝은/어두운 모드 PNG로 저장
- `--probe-option-input`, `--probe-escape`, `--probe-input-sources`: 설치본과 같은 인증서로 서명된 테스트용 앱을 `open -n`으로 실행해, 같은 접근성 권한으로 실행 중인 gksdud의 실제 입력 경로 확인
- `tests/virtual-keyboard`: 합성한 Caps Lock 이벤트는 잠금을 바꾸지 않아, Karabiner 가상 키보드로 실제 HID 입력을 만들어 확인
