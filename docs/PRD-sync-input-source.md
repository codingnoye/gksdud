# PRD: 다른 Mac과 한영 상태 동기화

## 1. 요약

유니버설 컨트롤로 Mac 두 대를 한 키보드로 쓸 때, 한쪽에서 한영을 바꾸면 다른 쪽도 같은 상태가 되게 합니다.
가장 최근에 바꾼 상태가 기준입니다. 첫 버전은 한국어와 영어만 맞춥니다.

## 2. 담당

| 이름 | 역할 | 비고 |
| --- | --- | --- |
| channprj | 기획, 구현, 두 대 실기기 검증 | 브랜치 `sync-input-source` |

## 3. 배경

- gksdud는 Mac마다 따로 한영 상태를 가집니다. 유니버설 컨트롤 지원은 "넘어간 키가 그 Mac에서 잘 전환되게" 하는 것까지입니다.
- 그래서 커서를 옆 Mac으로 넘기면 한영 상태가 달라져 있을 수 있고, 첫 글자를 잘못 치고 나서야 알게 됩니다.
- 대소문자는 이미 보내는 Mac 키보드의 Caps Lock을 따라가도록 맞춰져 있습니다. 한영 상태만 남았습니다.

### 내장 기능으로 되는지 검토한 결과

결론: **내장 기능만으로는 안 됩니다.** 앱이 값을 실어 보낼 수 있는 양방향 통로가 없습니다.
그래서 Apple의 공개 네트워크 API로 작은 통로를 직접 만들고, 유니버설 컨트롤은 "언제 다시 맞출지"의 신호로 씁니다.

| 후보 | 판단 | 이유 |
| --- | --- | --- |
| 유니버설 컨트롤의 키 전달 | 통로로는 불가, 신호로 활용 | 키보드가 있는 Mac → 커서가 있는 Mac 한 방향뿐이고, 커서가 넘어가 있을 때만 흐릅니다. 실제로 누른 키와 Caps Lock 값만 갑니다. 앱이 만든 키는 넘어가지 않습니다. 커서가 없는 쪽 Mac은 한영 키를 아예 보지 못합니다. |
| 유니버설 클립보드 | 불가 | 사용자의 클립보드를 덮어써야 합니다. 받는 쪽은 붙여넣을 때에야 내용을 가져오고 1초 이상 걸립니다. |
| Handoff (`NSUserActivity`) | 불가 | 사용자가 Dock 아이콘을 눌러야 넘어갑니다. 조용히 값을 보낼 수 없습니다. |
| iCloud 키-값 저장소 | 불가 | 반영이 수 초~수 분 걸리고 횟수 제한이 있습니다. iCloud 권한 설정도 필요합니다. |
| 유니버설 컨트롤 내부 통신 (Rapport) | 불가 | 비공개 API이고 Apple 전용 권한이 필요합니다. |
| **Network.framework + Bonjour** | **채택** | 공개 API입니다. 같은 네트워크의 상대를 자동으로 찾고 수 ms 안에 전달합니다. |

유니버설 컨트롤에서 가져다 쓰는 것:

- 커서가 옆 Mac으로 넘어가는 순간(유니버설 컨트롤이 맨 앞 앱이 됨)에 최근 상태를 한 번 더 보냅니다. 그 사이 어긋난 것이 있어도 타이핑을 시작하기 전에 맞춰집니다.

## 4. 목표

- 커서를 옆 Mac으로 넘겼을 때 한영 상태가 이미 같아서, 첫 글자부터 원하는 언어로 입력된다.

성공 기준:

- 한쪽에서 한영을 바꾸면 0.3초 안에 다른 쪽도 바뀐다 (같은 네트워크).
- 한영 키를 연달아 10번 눌러도 두 Mac이 서로 주고받으며 계속 바뀌는 일이 없다.
- 한쪽이 잠들었다 깨어나면 30초 안에 다시 연결되고, 더 최근에 바꾼 쪽 상태로 맞춰진다.
- 기능을 끄면 네트워크를 전혀 쓰지 않는다 (기본값 꺼짐).

## 5. 대상 사용자

- Mac 두 대 이상을 유니버설 컨트롤로 묶어 한 키보드로 쓰는 한국어 사용자.
- 두 Mac 모두 gksdud가 설치되어 있고 같은 네트워크에 있어야 합니다.

제약:

- 화면 공유, 원격 데스크톱 같은 원격 접속은 대상이 아닙니다.
- 로컬 네트워크 권한을 허용해야 합니다 (처음 켤 때 macOS가 묻습니다).

## 6. 가치

- 얻는 것: 어느 Mac에서 치든 한영 상태가 하나처럼 느껴집니다.
- 피하는 것: 커서를 넘길 때마다 "지금 한글인가 영어인가"를 확인하거나 첫 글자를 지우고 다시 치는 일.
- 비용: 코드 한 번 입력, 권한 창 한 번.

## 7. 해결 방법

### 7.1 사용 흐름

1. 두 Mac에서 설정 → 추가기능 → 기타의 **동기화 코드**에 같은 문구를 넣습니다.
2. **다른 Mac과 한영 상태 동기화**를 켭니다. macOS가 로컬 네트워크 권한을 물으면 허용합니다.
3. 이후로는 한쪽에서 한영을 바꾸면 다른 쪽도 바뀝니다.

연결 상태는 `gksdud status`의 `sync` 줄에서 봅니다 (`on (연결 1대)`).

### 7.2 기능

| 기능 | 내용 |
| --- | --- |
| 동기화 단위 | 한국어/영어만. 받은 쪽은 "최근에 쓴 한국어/영어 입력 소스"로 전환합니다 (`gksdud source ko`와 같은 경로). 두 Mac의 입력 소스가 달라도 됩니다. |
| 다른 언어 | 보내지 않습니다. 모르는 언어를 받으면 무시하므로, 나중에 언어를 늘려도 예전 버전과 섞어 쓸 수 있습니다. |
| 최근 상태 기준 | 바뀔 때마다 `{언어, 바뀐 시각}`을 보냅니다. 받은 쪽은 자기가 아는 것보다 최근일 때만 따릅니다. |
| 되울림 방지 | 상대가 시켜서 바뀐 것은 다시 보내지 않습니다. |
| 다시 맞추기 | 연결될 때와 커서가 옆 Mac으로 넘어갈 때 최근 상태를 한 번 더 보냅니다. |
| 상대 고르기 | 동기화 코드가 같은 Mac끼리만 연결됩니다. 코드는 암호화 키로 쓰이고 네트워크로 나가지 않습니다. 사무실에서 다른 사람의 gksdud와 섞이지 않게 하는 장치입니다. |
| 앱별 입력 소스 | 동기화를 켜면 "앱 포커스 시 입력 소스 전환"이 꺼집니다. 반대로 그 기능을 켜면 동기화가 꺼집니다. 서로 덮어쓰기 때문입니다. |
| 대소문자 | 동기화하지 않습니다. 기존대로 보내는 Mac 키보드의 Caps Lock을 따릅니다. |
| 건너뛰는 상황 | 따로 처리하지 않습니다. 단, 잠금 화면에서는 보내지도 받지도 않습니다 (잠금 화면이 영어를 고르는 것이 상대에게 퍼지지 않게 하는 한 줄). 풀릴 때 다시 적용하는 처리는 없고, 다음 "다시 맞추기"에서 맞춰집니다. |
| CLI | `gksdud set sync=on`, `gksdud get sync`, `gksdud status`에 연결 수 표시. 코드는 설정 창에서만 넣습니다. |

### 7.3 기술

- 찾기: Bonjour 서비스 `_gksdud-sync._tcp`. 실행할 때마다 새로 만든 임의의 이름으로 알립니다 (컴퓨터 이름을 알리지 않음).
- 연결: 두 Mac 중 이름이 작은 쪽이 겁니다. 그래서 한 쌍에 연결이 하나입니다.
- 보안: 동기화 코드를 SHA-256으로 바꾼 값을 TLS 사전 공유 키로 씁니다. 코드가 다르면 연결 단계에서 실패합니다.
- 메시지: WebSocket 메시지 하나에 JSON `{"language":"ko","at":1731920000.123}`. 256바이트를 넘으면 받지 않습니다.
- 시각: 각 Mac의 시계를 쓰되, 새 변경은 항상 "마지막으로 아는 시각보다 뒤"로 찍습니다. 두 Mac의 시계가 조금 달라도 연결 중에는 순서가 뒤집히지 않습니다.
- 끊김: 끊기면 5초 뒤 다시 겁니다. 잠에서 깨면 새 이름으로 다시 알려서 상대가 바로 다시 겁니다.
- 코드 위치: `InputSourceSync.swift` 한 파일. 보내기는 입력 소스 변경 알림에서, 받기는 기존 CLI `source` 경로로.

### 7.4 가정 (아직 확인하지 못한 것)

| 가정 | 확인 방법 |
| --- | --- |
| 커서가 옆 Mac에 가 있는 동안(유니버설 컨트롤이 맨 앞)에도, 이쪽 Mac에서 단축키 방식 전환이 동작한다. | 두 대로 확인. 안 되면 그 상태에서만 입력 소스를 직접 선택하는 방식으로 바꿉니다. |
| 이쪽 Mac이 만든 전환용 F-키가 유니버설 컨트롤을 타고 옆 Mac으로 넘어가지 않는다. | 두 대로 확인. 넘어가면 서로 계속 바뀌는 증상이 납니다. |
| 사용자가 치고 있지 않은 Mac의 한영이 바뀌어도 불편하지 않다. | 며칠 써 보고 판단. |
| 두 Mac이 같은 네트워크에 있다. | 다른 네트워크에서도 쓰려면 기기 간 직접 연결(AWDL)을 켜야 하는데, Wi-Fi 지연이 생길 수 있어 첫 버전에서는 뺐습니다. |

이 Mac 한 대(macOS 27.0.1)에서 확인한 것: Bonjour로 서로 찾기, 같은 코드끼리 연결, 다른 코드는 거부, 메시지 왕복.
